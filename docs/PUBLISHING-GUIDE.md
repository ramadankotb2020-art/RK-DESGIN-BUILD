# إضافة مشروع ونشر الموقع — RK Design Studio

## الطريقة المعتمدة
المصدر الأساسي هو فولدرات جهازك / GitHub، وليس لوحة KV القديمة. تعديل هنا أو على GitHub لا ينتقل تلقائيًا لجهازك؛ اعمل Pull قبل التعديل، ثم Commit وPush بعد المراجعة. احتفظ بنسخة احتياطية من صورك الأصلية لأن أداة ضغط الوسائط القديمة قد تستبدلها أو تحذف الأصل بعد التحويل.

1. حدّث نسختك المحلية بكل ملفات هذا التعديل، وليس ملف BAT وحده؛ أصبحت عملية البناء تحتاج `scripts/build-pages.js` و`scripts/enhance-pages.js` و`site.config.json` وملفات الواجهة الجديدة.
2. أنشئ فولدر المشروع داخل `images/projects-by-name/interior` أو `exterior` أو `graphic`.
3. أضف صورة غلاف وصور المشروع. أول اسم صورة أبجديًا هو الغلاف؛ استخدم `01-cover.webp` أو JPG/PNG. الصور الأصلية لا يعاد تسميتها آليًا.
4. أضف `info.txt` بترميز UTF-8. مفاتيحه الاختيارية:

```text
العنوان: [اسم المشروع الحقيقي]
التصنيف: [مثل مطاعم أو شقق سكنية أو هوية بصرية]
الموقع: [الموقع الفعلي إن توفر]
السنة: [السنة الفعلية إن توفرت]
المساحة: [المساحة الفعلية إن توفرت]
الوصف: [شرح حقيقي للمطلوب والحل والمخرجات]
الفكرة: [الفكرة التصميمية]
الخدمات: [خدمة فعلية], [خدمة أخرى]
الوسوم: [وسم مناسب], [وسم آخر]
عنوان SEO: [عنوان وصفي فريد]
وصف SEO: [ملخص طبيعي للمشروع]
وصف الصورة: [وصف الغلاف بدون حشو كلمات]
الرابط: [اسم-رابط-ثابت-بدون-مسافات]
الحالة: published
فيسبوك: لا
مميز: نعم
```

القيم بين الأقواس شرح وليست بيانات توضع حرفيًا. احذف أي حقل لا تعرف قيمته؛ لا تكتب موقعًا أو سنة غير مؤكدة. سطر الوصف حاليًا سطر واحد؛ لا يوجد محرر Rich Text.

التصنيفات الممكنة تشمل: تصميم داخلي، تصميم خارجي، لاندسكيب، تصور ثلاثي الأبعاد، جرافيك، هوية بصرية، مطبوعات وتغليف. اختر النص المناسب في `التصنيف` لعرضه في الفلاتر. يمكن تسجيل مفتاح آلي في `نوع المشروع` مثل `interior`, `exterior`, `landscape`, `3d`, `graphic`, `branding`, `printing`. القسم الأب يظل حسب فولدر المشروع، فلا يتم اختراع قسم أعمال فارغ أو نقل أعمالك تلقائيًا.

### الحالات
- `الحالة: draft` أو `الحالة: مسودة`: لا تدخل بيانات الموقع ولا sitemap ولا قائمة Facebook.
- غياب الحالة أو `published`: يظهر المشروع كما كانت تعمل المشاريع القديمة.
- `فيسبوك: نعم`: يسمح بتحضير وإرسال المنشور بعد تفعيل الربط؛ الحالة الفعلية `facebook_posted` ومعرف المنشور تحفظ في سجل GitHub Issues، وليست نفس حالة ظهور المشروع على الموقع.
- مسودات الصور ليست خزنة خاصة: الصور داخل مستودع عام أو مجلد الصور المنشور يمكن الوصول إليها بالمسار حتى لو لم توجد صفحة للمشروع. لا ترفع مواد سرية بهذه الطريقة.

### الفيديوهات
ضع فيديو MP4 أو WebM في فولدر المشروع مع صورة غلاف واحدة على الأقل. البناء يدرج الملف الفعلي في معرض المشروع ويحدد أول فيديو/cover.mp4 لمعاينة الكارت. لا يصنع فيديو من الصور ولا يسحب فيديو المشروع إلى بانرات أخرى. فيديوهات الهيرو لها مسارات محددة في `js/slides.js` والبانرات في `js/parallax.js`.

### تحديث جهازك
شغّل `update-site.bat` وانتظر `LOCAL UPDATE COMPLETED SUCCESSFULLY`. يعمل ضغط الوسائط الموجودة ثم بناء بيانات المشروع وصفحاته وSEO. لا يرفع إلى GitHub ولا ينشر الموقع بنفسه.

يمكن للمطور تشغيل `npm ci` ثم `npm run build` لتحديث الصفحات بدون ضغط/استبدال الوسائط. `npm run update` يضغط الوسائط أولًا. لا يوجد أي استدعاء لتوليد فيديوهات في هذه الأوامر.

النتيجة تشمل `js/projects-data.js` و`projects/` و`images/responsive/` و`sitemap.xml` و`social-posts.json` و`.generated-projects.json`. ارفع جميع الملفات المعدلة والجديدة واحفظ عمليات الحذف أيضًا؛ GitHub Desktop أسهل من رفع ملفات منفردة من المتصفح.

## معاينة محلية
شغّل `python serve-nocache.py` وافتح `http://localhost:8000`. الروابط الجديدة ذات المجلدات `/projects/.../` تحتاج خادم HTTP لمعاينة كاملة؛ فتح index.html مباشرة كملف لم يعد الاختبار الموصى به. لا تختبر APIs الخاصة بـ Cloudflare بهذا الخادم البسيط.

## Cloudflare Pages — إعداد خارجي مرة واحدة
بعد مراجعة التعديلات ودمجها في فرع الإنتاج المتصل باستضافتك:
- Build command: `npm run deploy:build`
- Build output directory: `dist`
- Node.js: 22 LTS (أو نسخة تدعم إصدار sharp الموجود).
- Production branch: فرع الإنتاج الذي تستخدمه بالفعل. عمل هذه الجلسة محفوظ على `arena/01a0819b-rk-desgin-build`، وليس منشورًا تلقائيًا على الإنتاج.
- يحتفظ `functions/` بمكانه في جذر المستودع لتكتشفه Cloudflare؛ `_routes.json` يقصر تشغيله على `/api/*` بدل تشغيل Middleware لكل صورة وصفحة.
- `dist` يتولد تلقائيًا ولا يرفع إلى Git. يستبعد مستندات التطوير والنسخ الاحتياطية وnode_modules وملفات info.txt.
- لوحة `admin.html` القديمة ما زالت موجودة ومعلّمة noindex وبها تنبيه أنها غير مرتبطة بالنشر عبر الفولدرات. لا تستخدمها كمصدر ثانٍ لنفس المشاريع.

دومين الإنتاج الحالي موجود في `site.config.json`: `https://rk-desgin-build-2an.pages.dev`. عند اعتماد دومين جديد: غيّره هناك وأعد البناء، وأضف تحويلات الدومين القديم في Cloudflare. لا تغيّره إلى دومين لا تملكه.

## الروابط القديمة
`project.html?id=...` ما زال يقبل المعرف القديم ويحوّل عبر JavaScript إلى الصفحة الجديدة. الروابط الجديدة صفحات HTML فعلية مع canonical وOG في المصدر. هذه التحويلات ليست 301 على الخادم؛ يمكن إضافة تحويلات Edge لاحقًا. المعرّفات القديمة المتصادمة لا يمكن استنتاج أي مشروع كان المقصود منها؛ يحتفظ المسار القديم بأول تطابق كما سابقًا. المعرّفات الجديدة فريدة.

حدد سطر `الرابط` مرة واحدة ولا تغيّره بعد النشر. تغيير اسم الفولدر قد يغير معرف المشروع، وتغيير العنوان يغير الرابط التلقائي إذا لم تحدد رابطًا ثابتًا. لا يوجد نظام إعادة تسمية/تحويلات تاريخية تلقائي.
